### 2.2 동사 분포

원고 어댑터는 spaCy에서 `pos_ == VERB`, 알파벳 원형, 원형 길이 2자 이상인 토큰을 원형별로 합칩니다. AUX는 포함하지 않습니다. 단어 분모는 원본 `hedge_verbs.is_word` 판정을 사용합니다.

```text
원고 동사 /10k = 동사 원빈도 ÷ 해당 절 단어 수 × 10,000
분야 동사 /10k = 표본 논문별 동사 /10k 값의 산술평균
```

분야 상위 10개는 출현 논문 수 내림차순 → 분야 /10k 평균 내림차순 → 동사 이름 순으로 정렬합니다. 원고 상위 10개는 원빈도 내림차순 → 이름 순입니다. 존재하는 절의 단어 수가 0보다 큰 논문만 비교에 참여하며 누락 절을 0으로 채우지 않습니다.

겹침은 원고 상위 동사와 분야 상위 동사의 교집합 개수입니다. 분야 상위 중 원고에 전혀 없는 동사를 별도로 표시하고, 원고에서 2번 이상 썼으나 분야 표본에서 0~1편에 등장한 동사는 희귀 사용으로 안내합니다. 이 정확한 희귀도 계산은 논문별 전체 동사 분포가 있는 GNU 기준에 해당합니다.

### 2.3 헷지 동사 판정

헷지는 명제에 대한 저자의 확신을 낮추는 인식적 용법입니다. 같은 `indicate`, `appear`, `estimate`라도 문맥에 따라 다르게 판정합니다.

| 판정 | 뜻 | 합계 반영 |
|---|---|---|
| Hedge | 잠정 추론·가정·예상 | 포함 |
| N | 관찰·방법·수치·도식 지시 등 비헷지 | 제외 |
| U | 타 연구 귀속, 강조와 상쇄 등 판단 유보 | 제외 |

원고에 후보 문장과 앞뒤 문장, 자동 사유를 제공합니다. 연구자가 판정·메모를 저장하면 재집계합니다. 기존 PDF 작업과 기준 생성에서는 연구자 판정 → 검토판정 → 자동판정 순으로 사용합니다.

```text
헷지 /10k = Hedge 후보 수 ÷ 단어 수 × 10,000
헷지 /100동사 = Hedge 후보 수 ÷ lexical verb 수 × 100
```

GNU 판정 문서는 JOC 6편의 후보 127건 검토(Hedge 74, N 45, U 8)를 바탕으로 작성됐다고 설명합니다. 방법 절이 표본에서 0건이었다는 사실은 모든 논문의 방법 절이 반드시 0이어야 한다는 규칙이 아닙니다.

### 2.4 선행연구 구조

서론은 인용 문장이 소개하는 선행연구 흐름을 토픽으로 묶습니다. 자동값은 문단 기준이며 의미 토픽은 연구자가 수정해야 합니다. 토픽 조직은 주제 통합·논문별 나열·혼합입니다. 결과·논의 인용 기능은 비교·일치, 비교·차이, 해석 근거, 방법·자료 출처, 배경 정보입니다.

자동 단서가 없으면 배경 정보로 분류될 수 있어 확인이 필요합니다. `(제외)` 접두사의 토픽은 토픽 수·토픽별 문헌 통계에서 제외됩니다. 현재 구현은 번호식 인용을 처리하며 `[1–3]`, `[3a,b]`, 내부 표지 `⟦c:1–3⟧`를 사용합니다. PDF 인용 전용 추출 경로는 ACS 위첨자를 보존하려고 설계되었습니다.

주요 요약값은 서론 인용 표지 /100단어, 결과·논의 표지 /1,000단어, 토픽 수, 토픽당 고유 문헌 수 평균, 서론·결과논의 고유 문헌 수, 결과·논의에 새로 등장한 문헌 수, 저자 통합형 인용 문장 비율, 기능별 문장 비율입니다. 분모·단위가 서로 달라 같은 척도로 비교하면 안 됩니다.

### 2.5 과거 16편과 현재 데이터의 차이

원본 README는 JOC 6편·IC 5편·CM 5편(2010–2015)의 분석을 언급합니다. 그러나 통합 당시 원본 저장소에는 그 PDF·엑셀·완성 분야 기준 자료가 없었습니다. 스크린샷에 보이는 JOC 6편 기준값을 현재 앱에 임의 복원하지 않았습니다.

현재 JOC 20편 마크다운 기준과 과거 화면의 JOC 6편 GNU 기준은 자료와 엔진·분모·통계가 다릅니다. 같은 원고라도 수치가 달라집니다. IC 예시를 선택해 유기화학 원고를 분석하는 경우에는 분야 차이까지 추가됩니다.

### 3.2 입력과 절 코드

| 앱 입력 키 | Stage 1 코드 | 뜻 |
|---|---|---|
| INTRO | INT | 서론 |
| M | MET | 실험·방법·계산 |
| RD | RD | 통합 결과·논의 |
| CONCL | CON | 결론 |
| 원본 자료 전용 | RES, DIS | 분리된 결과와 논의 |
| 기본 집계 제외 | ABS | 초록: CLI 옵션으로만 포함 |

마크다운에서 RES만 있고 DIS·RD가 없으면 엔진이 RES를 RD로 묶습니다. RES와 DIS가 모두 있으면 별도 집계합니다. 앱 입력에는 RES·DIS를 각각 받는 칸이 없으므로 분리 기준만 있는 경우 RD 비교값이 없을 수 있습니다. 실제 섹션별 n과 제공 행을 확인해야 합니다.

### 3.3 분모와 통계

`prose=false` 문장은 집계·분모에서 제외합니다. NMR·원소분석 등의 NONPROSE 판정이 포함됩니다. 본문의 단어 수는 spaCy의 `token.is_alpha`가 참인 토큰 수입니다. 공백으로 나눈 단어 수와 같지 않습니다.

```text
논문별 지표 /1k = 해당 절의 표현 수 ÷ 해당 절 알파벳 토큰 수 × 1,000
분야 대표값 = 논문별 /1k 값들의 중간값
범위 = 논문별 /1k 값들의 최소–최대
n = 그 절·지표에 유효한 값이 있는 논문 수
```

논문별 /1k를 소수 둘째 자리로 반올림한 뒤 중간값을 계산하고 결과도 둘째 자리로 반올림합니다. 전체 논문의 표현 수와 단어 수를 합쳐 나눈 값이 아닙니다. `words` 지표는 /1k가 아니라 실제 분석 단어 수입니다. MET의 헷지·강조 정규화 값은 빈칸이며 0이라는 뜻이 아닙니다.

공통 동사는 섹션별 동사 분포에 참여한 논문 중 `ceil(n/2)`편 이상에 출현한 VERB 원형입니다. 빈도 0인 참여 논문도 중간값 계산에 반영하고 중간값 내림차순으로 정렬합니다. 상위 10개보다 적을 수 있으므로 겹침 표시가 `2/5`처럼 나올 수 있습니다. 공통 목록의 n은 지표별 n과 구현상 항상 같다고 가정하지 않습니다.

### 3.4 표현 범주와 중복 처리

헷지·강조 어휘와 다어절 표현은 원본 README가 설명하는 Hyland (2005) 목록 및 화학 문맥 제외 규칙에 기반합니다. 보고동사는 `engine_local`이 선행연구 귀속(`role=prior`)으로 분류한 표현을 셉니다. 보고동사 영역과 겹친 토큰은 헷지·강조에서 중복 집계하지 않습니다.

문자 그대로의 `show/find`, 수치 앞 `about`, 검출 가능성, 관용구 등은 규칙에 따라 합계에서 제외하거나 review 범주에 남습니다. `can`이나 정도·빈도 표현을 단순 문자열 출현만으로 모두 헷지로 세지 않습니다. `evidence.csv`에는 문서·문장·절·범주·표현·원형·문장(최대 300자)을 기록합니다.

### 3.5 두 가지 품질 검사

| 입력 | 적용 검사 | 적용하지 않는 검사 |
|---|---|---|
| 원본 PDF | 인용 회수율 ≥95%, 열린 문장 ≤5%, 여백 누출 0; 레이아웃 그림 | 마크다운 변환 품질 검사 |
| 기존 마크다운 | 서론·결과논의 존재, 절 순서, 전처리 본문 최소 길이, 집계 처리 검사 | PDF 좌표·인용 회수율 검사 |

마크다운의 구조 통과는 PDF 추출 품질 통과와 동의어가 아닙니다. 전처리 어댑터의 최소 길이는 공백 분할 근사값이고 엔진이 다시 검사하는 분석 단어 수는 알파벳 토큰 수입니다. 어댑터 통과 후에도 엔진의 1,000단어 검사가 실패하면 전체 재계산 작업이 실패할 수 있습니다.

### 3.6 포함 예시와 검증 한계

원본 저장소의 공개 예시는 `examples/IC_2010-2015_5편/`입니다. README의 시험 범위는 IC 5편·CM 5편·JOC 6편이지만 공개 예시 CSV가 세 분야 전부 들어 있다는 뜻은 아닙니다. IC 예시 `evidence.csv`의 문장은 원저작자가 비워 공개했습니다.

원본 README는 헷지·강조 448건을 검토하여 오판 61건 중 59건을 규칙으로 거른다고 설명합니다. 이는 독립 검증 세트의 정확도가 아닙니다. 검토는 Claude에 의한 판정이며 사람과의 일치도는 측정하지 않았고 보고동사·일반 VERB 분포도 별도 검증되지 않았다고 명시합니다. 새 분야에서는 표현별 근거를 표본 검토해야 합니다.

현재 포함 기준은 예비값입니다. [현재 기준선 상세](current-baselines.md)와 [업데이트 절차](baseline-update.md)를 함께 읽어야 수치의 출처와 변경을 재현할 수 있습니다.

## 5. 마크다운 전처리 세부 규칙

현재 어댑터는 다음 순서로 처리합니다. 논문의 논리 구조를 의미적으로 추론하는 모델이 아니라 명시적 문자열·블록 규칙입니다.

1. 루트 분야 폴더의 `.md`를 정렬해 읽고 선택 목록이 있으면 해당 이름만 처리합니다.
2. 문자 그대로의 `\t`를 탭으로 바꾸고, 인식 가능한 헤딩 앞에 빈 줄을 넣어 문단 블록을 나눕니다.
3. 첫 블록이 `[포맷:`으로 시작하면 Kordoc 메타데이터·목차·변환 경고 블록으로 보고 제외합니다.
4. Markdown 헤딩 표식·굵게 표식·절 번호를 정리한 뒤 Introduction/Background, Results and Discussion, Results, Discussion, Experimental/Methods/Computational, Conclusions, References 등 정규식으로 절을 정합니다.
5. 인식 전 본문과 참고문헌·감사의 글·저자 정보·SI 구역은 분석 본문에서 제외합니다.
6. 그림·표·스킴·차트 캡션 시작 블록, 번호식 참고문헌, `|`·`<table`로 시작하는 표, 이미지, 짧은 저널 러닝 헤더, 짧은 하위 헤딩 등을 제외합니다.
