# 프로젝트 전체 안내

## 1. 목적과 분석 대상

출판된 같은 분야 논문에서 섹션별 표현 사용 양상을 얻고, 사용자가 입력한 영어 원고와 비교합니다. 주요 분석은 동사 분포, 인식적 유보를 나타내는 헷지 표현, 선행연구의 토픽·조직·인용 기능입니다.

예를 들어 유기화학 원고의 서론에서 자주 쓴 동사가 JOC 표본의 공통 동사와 얼마나 겹치는지, 헷지 빈도가 그 표본의 중간값·범위와 어떻게 다른지 확인할 수 있습니다. 기준 범위에서 벗어났다는 사실만으로 잘못된 문장이라고 판정하지 않습니다. 논문의 분야·세부 주제·연도·문서 길이에 따라 표현이 달라집니다.

한국어 화면을 제공하지만 분석 모델과 규칙은 영어 연구논문용입니다. 문장 의미를 생성형 AI로 평가하거나 자동 교정·재작성하는 기능은 현재 구현에 없습니다. API 키가 필요한 LLM 호출도 없습니다.

## 2. 기능과 구현 범위

| 기능 | 구현 방식 |
|---|---|
| 원고 입력 | 서론·방법·결과·논의·결론에 해당하는 네 입력 칸, 전체 원고 헤딩 분할 |
| 파일 불러오기 | TXT, DOCX, 텍스트 PDF에서 본문 추출 |
| 예시 원고 | `ex.txt` 내용을 프런트엔드의 초기 서론 문자열에 포함 |
| 동사 비교 | spaCy VERB 원형별 빈도, 상위 동사, 분야 공통 동사와 겹침 |
| Stage 1 표현 비교 | 헷지·강조·선행연구 보고동사·전체 동사 /1k, 문장별 근거 |
| 기존 GNU 헷지 검토 | Hedge/N/U 예비판정, 연구자 수정·메모·재집계 |
| 선행연구 분석 | 서론 토픽·문헌 수·조직, 결과·논의 인용 기능; 연구자 수정 |
| PDF 분석 | 기존 GNU 분석과 Stage 1 기준선 생성 모드 |
| 내보내기 | 기존 작업의 동사·선행연구 엑셀, Stage 1·관리자 재계산 산출물 ZIP |
| 프로젝트 문서 | 상단 문서 메뉴 `/guide`, 왼쪽 문서·절 목차, MD 다운로드 |
| 관리자 | 현재 기준, 보관 버전, 마크다운 선택·재계산, 적용·복원, 변경 이력 |
| 저장 | 외부 DB 없이 루트 `data/`의 JSON 및 산출물 |

Stage 1 자동 판정을 기존 Hedge/N/U 수정 API로 덮어쓰는 기능은 제공하지 않습니다. GNU 검토 결과와 Stage 1 규칙 집계는 다른 체계입니다.

## 3. 기술 구성

| 영역 | 구성 |
|---|---|
| 서버 | FastAPI, Pydantic, Uvicorn |
| 화면 | HTML, 일반 JavaScript, 공유 CSS; 별도 Node 빌드 없음 |
| 영어 분석 | spaCy 3.8.11, en_core_web_sm 3.8.0 |
| PDF | PyMuPDF, pdfplumber, pypdfium2, Pillow; 추출기 조건에 따라 Poppler |
| 엑셀 | openpyxl |
| 저장·식별 | JSON, UUID, SHA-256, 임시 파일 원자적 교체 |
| 백그라운드 | ProcessPoolExecutor 1개 워커 및 별도 CLI 프로세스 |
| 배포 | Render 네이티브 Python, Python 3.12, Uvicorn 1개 워커 |

일부 일반 패키지는 `requirements.txt`에 버전 범위로 지정되어 있습니다. 완전한 전이 의존성 잠금 파일은 없으며, 분석 엔진·모델은 고정 버전을 검사합니다.

## 4. 로컬 설치 및 실행

프로젝트 루트에서 실행합니다. Python 3.12를 권장하며 Render도 3.12를 사용합니다.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip install 'https://github.com/explosion/spacy-models/releases/download/en_core_web_sm-3.8.0/en_core_web_sm-3.8.0-py3-none-any.whl'
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8001 --workers 1
```

- 원고 화면: http://127.0.0.1:8001/
- 관리자: http://127.0.0.1:8001/admin
- 프로젝트 문서: http://127.0.0.1:8001/guide
- 대화형 API 문서: http://127.0.0.1:8001/docs
- 상태 확인: http://127.0.0.1:8001/api/health

`pip`와 서버 실행에 같은 Python 환경을 사용합니다. Stage 1 버전 검사 때문에 다른 spaCy·모델 버전이면 분석이 거절됩니다. `.venv-baseline`이 있으면 관리자 재계산은 그 안의 Python을 우선 사용하므로 이 환경도 버전을 맞춰야 합니다.

최초 실행 시 `data/`를 만들고 IC 5편 예시 및 네 분야 포함 기준을 등록합니다. 관리자 자격 정보와 초기 버전 이력도 생성합니다. 기존 관리자 레지스트리가 있으면 현재 적용 포인터를 초기 기준으로 자동 교체하지 않습니다.

PDF 원본 Stage 1 추출은 2쪽 이상 텍스트 논문이 필요합니다. Poppler `pdftotext`가 있으면 사용하며 없을 때는 원본 추출기의 대체 경로를 따릅니다. xpdf의 동명 실행 파일이 먼저 발견되면 원본 엔진이 실행을 막습니다.

## 5. 화면 사용

### 5.1 원고 입력

1. 왼쪽 **분야**에서 원고에 맞는 기준을 선택합니다. 기본 네 분야는 CM·IC·JOC·JPC_C입니다.
2. **분할**은 섹션별 입력, **전체**는 전체 원고 입력 후 헤딩 분할에 사용합니다.
3. 서론, 방법, 결과·논의, 결론에 본문을 넣습니다. 파일 불러오기는 본문 텍스트를 가져오는 동작이며 PDF 기준선 생성과 다릅니다.
4. 전체 원고 분할 후 배정되지 않은 텍스트와 각 섹션을 확인합니다. 헤딩 미인식은 직접 수정합니다.
5. 분석을 실행합니다. 원고 전체는 200,000자 이내여야 합니다.

TXT는 UTF-8(BOM 포함)을 우선 읽고 실패하면 CP949를 시도합니다. DOCX는 `word/document.xml`의 문단을 읽습니다. PDF는 텍스트 레이어를 사용하며 OCR을 수행하지 않습니다. 파일당 최대 50MB, DOCX 본문 XML 최대 10MB입니다.

`ex.txt`는 현재 `frontend/app.js`의 초기 입력 문자열에 반영되어 있습니다. 서버가 매번 파일을 읽는 구조가 아니므로 예시를 바꾸려면 두 파일의 내용을 함께 맞춰야 합니다.

### 5.2 분석 결과

왼쪽 탐색에서 **동사 분포**, **헷지 표현**, **선행연구 구성**을 전환합니다. 입력 편집기와 결과는 오른쪽에서 번갈아 표시됩니다. 결과를 보는 동안 분야 선택을 잠가 결과와 기준의 표시가 달라지는 일을 막고, 입력으로 돌아가면 원고를 보존합니다.

동사 표의 왼쪽은 분야 공통 동사, 오른쪽은 원고에서 많이 쓴 동사입니다. Stage 1의 `기준 목록에 없음`은 해당 동사가 모든 논문에서 0건이라는 뜻이 아닙니다. 공통 동사 CSV에 기록되지 않았다는 뜻입니다.

300단어 미만 섹션에는 빈도 해석 주의 문구가 표시됩니다. 단어 수가 적으면 표현 1건의 차이가 정규화 빈도를 크게 바꿉니다.

선행연구의 자동 토픽은 문단 단위입니다. 의미 토픽을 병합·분리하거나 조직 유형을 확정할 때 사람이 내용을 검토해야 합니다. `(제외)`로 시작하는 토픽은 토픽 통계에서 빠집니다.

### 5.3 PDF 작업

- 기존 GNU 모드: 1~20개 PDF를 분석하고 판정을 검토한 뒤 완료 작업을 묶어 기준을 만듭니다. 동일 PDF는 기준 생성 시 SHA-256으로 중복 제거합니다.
- Stage 1 모드: 2~10개 서로 다른 PDF로 추출 품질 검사와 기준선 생성을 수행합니다. 완료 시 독립 기준선을 자동 등록합니다.
- 네 분야 관리자 기준을 바꾸는 동작은 관리자 페이지의 재계산·적용입니다. PDF 작업에서 독립 기준을 만드는 것과 구분합니다.

## 6. 폴더 지도

```text
프로젝트 루트/
  backend/
    main.py                  FastAPI·작업·파일·기준·판정 API
    analysis.py              기존 GNU 엔진 어댑터·원고·선행연구 집계
    stage1.py                Stage 1 CSV 가져오기·원고/PDF CLI 연동
    admin.py                 관리자 인증·레지스트리·적용·이력
    admin_worker.py          고정 입력·규칙으로 마크다운 재계산
    documentation.py         docs 마크다운을 앱 문서 화면으로 제공
  frontend/
    index.html, app.js       원고·PDF 화면
    admin.html, admin.js     관리자 화면
    assets/style.css         공통 스타일
    assets/fonts/            SUIT·KIMM·IBM Plex Mono 및 출처/라이선스
  GNU_AI_Team/               첫 번째 원본 저장소의 통합 소스
  section-verb-hedge-baseline/ 두 번째 원본 저장소의 통합 소스
  CM/, IC/, JOC/, JPC_C/     분야별 논문 마크다운 각 25편
  baselines_markdown/        네 분야의 포함 기준 JSON·CSV·감사 자료
  scripts/                  마크다운 변환 어댑터·기준 JSON 마무리·Render 빌드
  tests/                    API·관리자·Stage 1 통합 검증
  docs/                     이 문서 모음
  ex.txt                    고정 원고 예시
  data/                     실행 데이터, Git 제외
  requirements.txt          Python 의존성
  .python-version           Render Python 3.12
  render.yaml               배포 선언
```

ZIP·PDF는 Git에서 제외합니다. 분야별 마크다운과 기준 산출물은 추적합니다. 두 원본 저장소의 코드는 현재 일반 파일로 통합되어 있으며 외부 패키지를 자동 갱신하는 구조가 아닙니다.

## 7. 화면 스타일

배경은 흰색, 본문 기본 색은 검정입니다. 본문 SUIT, h1 KIMM Bold(기계연구원), 숫자·코드 IBM Plex Mono를 로컬 자산으로 제공합니다. 보조 정보와 구분선은 별도 색을 사용합니다. 탐색·분야·결과 선택은 왼쪽에 배치하고 표의 모든 열은 좌측 정렬합니다. 현재 스타일은 `frontend/assets/style.css`에서 관리합니다.

## 8. 사용 시 한계

- 영어 일반 모델의 품사·원형 분석 오차와 화학 전문어 오인 가능성이 있습니다.
- ACS 중심 PDF 규칙이므로 다른 출판사 형식은 추출 실패 가능성이 있습니다.
- 스캔 PDF OCR, 한국어 형태소 분석, 저자-연도식 인용 자동 집계는 지원하지 않습니다.
- 마크다운의 읽기 순서·표로 들어간 본문·문장 잘림은 구조 검사만으로 모두 탐지하지 못합니다.
- 기준선은 표본의 기술 통계입니다. 분야 전체의 대표성, 유의성, 인과관계를 보증하지 않습니다.
- 현재 공용 분석 API는 관리자 로그인 없이 호출할 수 있습니다. 서비스 전체의 사용자 인증·개인별 결과 접근 통제는 구현되지 않았습니다.
- 파일 저장·프로세스 잠금은 단일 앱 프로세스 전제입니다. 워커·인스턴스를 늘리는 수평 확장은 별도 설계가 필요합니다.

더 자세한 계산과 한계는 [두 저장소와 분석 방법](analysis-and-upstream.md), 운영은 [배포 안내](render-deployment.md)를 확인합니다.
